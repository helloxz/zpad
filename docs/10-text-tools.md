# 文本工具（Base64 / MD5 / JSON / 行号）

状态：**待签收**（Base64 / MD5 / JSON 随 0.5.1 发布，行号与 JSON 整篇未发布）

## 背景

日常常需要对选中文本做 Base64 编解码、取 MD5、格式化或压缩 JSON。如果每个工具都在右键菜单里占一项，菜单会越来越长；因此只保留一个「工具」入口，具体工具放进它的子菜单。工具栏的「Aa」按钮也换成扳手按钮，打开同一套菜单。

大小写转换不放进「工具」：MyGo 编辑器自带的右键「转换」已经包含大写 / 小写 / 词首大写、四种命名转换和行操作，比应用的版本更全；应用菜单「编辑 → 大小写转换」也保留着，其中「反转大小写」是自带「转换」没有的。

## 需求

- 右键菜单只有一个一级项「工具」，它的子菜单按组列出：Base64、MD5、JSON、行号；不重复放大小写转换。
- 工具栏（macOS 上与标题栏合并的那条）在原来「Aa」的位置放一个扳手按钮，打开同一套菜单。
- 所有工具只处理**选中文本**，JSON 例外：文档语言为 JSON（`.json` / `.jsonc` / `.json5` / `.webmanifest`、按文件名识别的配置，或未命名文件在状态栏选了 JSON）且没有选中时，格式化与压缩作用于**整篇**；有选中时仍然只处理选中。文档只读或标签处于 Markdown 预览时不执行，菜单项置灰。
- 单次操作允许的选中文本总量上限 **512 KB**（UTF-8 字节），超过时提示并不改动；JSON 整篇上限 **8 MB**，格式化结果仍受 8 MB 输出上限约束。整篇替换是一步撤销，光标按行列保留，视图不跳动；重写后重新判定高亮。
- Base64 编码输出标准、带填充、单行；解码忽略空白与换行，兼容标准 / 无填充 / URL-safe / URL-safe 无填充四种。解码结果必须是 UTF-8，否则拒绝写入。
- MD5 提供 32 位小写、32 位大写、16 位小写、16 位大写；16 位是 32 位十六进制的第 9–24 个字符，不是另一种算法。
- JSON 格式化固定 2 空格缩进，保持成员顺序与数字、字符串的原始写法；压缩去掉所有无意义空白。格式化后的后续行对齐到选区起始行的缩进，避免嵌在代码里的值跳回行首；整篇格式化从行首开始，不加缩进。
- 行号：把序号写进正文的每一行开头，用于 m3u8 播放列表、清单这类需要自带序号的文本。四档分隔符：`01,`（播放列表、m3u8）、`01. `（文档清单）、`01) `、`01: `；补零到至少两位，行数超过 99 时按实际位数增长；编号从 1 开始，多选区按文档顺序连续编号。
- 多选区要么全部成功，要么全部不改；成功的替换是一步撤销，选区跟随结果。
- 非目标：Base64、MD5、行号对整个文档操作；JSON 排序 / 转换 YAML、自定义缩进；行号不做起始值 / 步长 / 分隔符模板 / 删除行号 / 重新编号。

## 交互

```
右键（编辑器正文）
├── （Markdown 文件）预览 Markdown
├── 转换 ▸            （MyGo 自带：大小写、命名转换、行操作）
├── 工具 ▸
│   ├── Base64 ▸      编码 / 解码
│   ├── MD5 ▸         32 位小写 / 32 位大写 / 16 位小写 / 16 位大写
│   ├── JSON ▸        格式化 / 压缩
│   └── 行号 ▸        01, / 01. / 01) / 01: 
├── 换行符 ▸
├── 编码 ▸
└── 关闭当前标签
```

- 工具栏按钮的菜单直接是上面「工具 ▸」里的四组。
- 没有选中时，JSON 文档的 JSON 组保持可用，两项直接作用于整篇，命名仍是「格式化 / 压缩」；纯文本文档的 JSON 组与其它组仍置灰。
- 系统菜单栏保持原样：编辑 → 大小写转换（含反转大小写）；不新增顶层「工具」菜单。
- 右键作用于被右键的那个标签，不依赖当前活动栏。

## 实现

- `internal/texttools/`：纯函数与测试。
  - `base64.go`：`EncodeBase64`、`DecodeBase64`（去空白、四种字母表、UTF-8 校验）。
  - `digest.go`：`MD5(s, mode)` 四种十六进制形式。
  - `jsonfmt.go`：`FormatJSON`、`MinifyJSON`。格式化用 Go 1.27 的 `encoding/json/jsontext` 流式编码器写出，先 `json.Valid` 校验、再检查嵌套深度（`MaxJSONDepth = 128`），输出写入限长 writer（`MaxJSONOutput = 8 MB`）。直接用 `json.Indent` 会被深嵌套输入按深度二次放大，1 MB 输入就能产出几十 GB。
  - `texttools.go`：`MaxInput = 512 KB` 与错误类型。
  - `lineno.go`：`CountLines`（末尾换行不算多一行）、`NumberLines(s, sep, first, width)`；只在行首插前缀，不重写缓冲区里的 `\n`，行尾仍由 Buffer 单独保存。
- `internal/app/selections.go`：从原来的大小写转换里抽出 `transformSelections` / `writeSelectionChanges`：先完成全部转换再一次性写入，从后往前改、重算偏移、恢复选区、`Buffer.Transact` 合成一步撤销。
- `internal/app/tools.go`：工具枚举、选区字节数、`runTextTool`、JSON 缩进对齐、错误文案映射，以及工具栏与右键共用的 `toolMenu`；菜单在打开时按当前选区决定置灰。JSON 整篇单独走 `runJSONWholeDoc`：`jsonWholeDoc` 只看文档语言（文件名的识别与状态栏选择共用同一个 `Language`），`runTextTool` 在没有选中时改走整篇；整篇用 `Buffer.Set` 一次替换（自带一步撤销），替换前记下光标行列与滚动位置、替换后夹取恢复，再调用 `applyLanguage` 重新判定高亮。行号单独走 `runLineNumbers`：`lineNumberPlan` 先按文档顺序数出每个选区的首行编号与总位数（最少两位），再用同一个 `transformSelections` 写入；`toolSelection` / `applyToolSelection` 抽出选区检查与收尾，供两套工具共用。
- `internal/app/view.go`：工具栏「Aa」换成扳手按钮；右键新增「工具」子菜单。大小写交给 MyGo 自带的「转换」，应用菜单的「编辑 → 大小写转换」不变。
- `internal/app/icons.go`：新增 `iconTools`（扳手）。
- 文案：`toolsMenu`、四组名称与 10 个工具项、6 条错误提示，中英各一份，`go tool mygo generate` 生成。

## 内存

工具不新增常驻结构，也不缓存结果。单次最坏情况：选区拷贝 512 KB，加上结果（Base64 约 683 KB，JSON 通常 1–3 MB，行号约 1.3 MB）与 rope 编辑的新节点，峰值几 MB，下一次 GC 回落。JSON 的输出上限保证深嵌套输入不会把内存顶高；撤销历史保留替换前的文本，属于编辑器既有行为。行号不需要额外索引，只为数行数和补零位数在计划阶段多读一次选区文本，仍在 512 KB 之内。

JSON 整篇的上限是 8 MB：整篇会先把文档拷成一份字符串，格式化输出再占最多 8 MB，加上 rope 节点与这一步撤销保留的旧文本，峰值几十 MB，仍在与打开同样大小的文件相当的范围内；实测 512 KB 约 3 ms、2 MB 约 11 ms、4 MB 约 19 ms（压缩约为一半），同步执行即可，不需要后台 goroutine。写回 rope 另测约 2 ms（4 MB）。

## 已知限制

- 多行文本按缓冲区内部的 LF 计算 MD5 / Base64；CRLF 文件保存到磁盘时是 CRLF，两者字节不同。
- JSON 只接受严格 JSON：注释、尾逗号、单引号会报错；不支持排序、去重或自定义缩进宽度。
- `.jsonc` / `.json5` 在 MyGo 里也识别为 JSON 语言，整篇处理仍走同一个严格解析器；带注释、尾逗号或单引号的文件会报错，需要先选中合法片段或改用纯文本语言。
- JSON 整篇输入超过 8 MB 直接拒绝；格式化结果超过 8 MB 也拒绝（约 6 MB 以上的紧凑 JSON），压缩只受输入上限约束。
- 没有单独的「格式化整篇 / 压缩整篇」菜单项：是否作用于整篇只看有没有选中。
- JSON 整篇替换后重新判定高亮：单行大 JSON 格式化后会恢复高亮，整篇压缩成一行超过 128 KB 时会关闭高亮，与重新打开该文件一致。
- JSON 格式化结果按选区所在行的缩进对齐，但如果选区不是从空白之后开始，就不加缩进。
- 错误详情（JSON 语法位置、Base64 非法字符）来自标准库，是英文技术信息；主提示已本地化。
- 系统菜单栏没有「工具」，只有编辑菜单里的「大小写转换」。
- 「工具」里没有大小写转换，右键的「反转大小写」不再提供；它还在编辑菜单里。
- 行号固定从 1 开始、步长 1、补零至少两位，不提供起始值、步长、分隔符模板、删除行号或重新编号；要给已经带序号的行重新编号，需要先删掉旧序号再运行一次。
- 选区不落在行首时，前缀插在选区起点，即按选区第一行处理，不向外扩张到整行；选区以换行结尾时，末尾空行不编号。
- 与其它文本工具一样，行号也受 512 KB 选中上限约束（约 1 万行）；更大的文本需要分段处理。

## 验收清单

- [ ] 右键菜单只有一个「工具」项，展开后是 Base64 / MD5 / JSON / 行号四组，不重复大小写转换
- [ ] 工具栏原「Aa」位置是扳手按钮，打开同样的四组菜单
- [ ] 没有选中时 Base64 / MD5 / 行号置灰，纯文本文档的 JSON 两项也置灰；JSON 文档的 JSON 两项可用并作用于整篇
- [ ] JSON 文档没有选中时，格式化 / 压缩改写整篇，菜单文案仍是「格式化 / 压缩」，一步撤销即可回退
- [ ] 整篇替换后光标行列与视图不跳到文末，CRLF 文件仍按 CRLF 保存
- [ ] 单行超长而暂停高亮的 JSON 在整篇格式化后恢复高亮
- [ ] 右键的大小写转换由 MyGo 自带的「转换」提供，编辑菜单仍可反转大小写
- [ ] Base64 编码输出带填充的单行结果；解码可处理换行、无填充与 URL-safe
- [ ] Base64 解码出非 UTF-8 数据时提示且不改动文本
- [ ] MD5 四种形式的长度与大小写正确，16 位为 32 位的中间 16 个字符
- [ ] JSON 格式化保持成员顺序，缩进 2 空格并对齐选区所在行
- [ ] JSON 深度或输出超限、语法错误时提示且不改动文本
- [ ] 选中超过 512 KB 时提示且不改动文本
- [ ] 小于等于 8 MB 的 JSON 整篇可用；超过 8 MB 不执行，格式化结果超过 8 MB 时提示且不改动文本
- [ ] 多选区工具一次撤销即可全部回退
- [ ] 行号四档正确：`01,` / `01. ` / `01) ` / `01: `；8 行补零到两位，超过 99 行按实际位数
- [ ] 只选中文档中间几行时，只有这些行加序号，其余行不变；末尾换行不会多出一个空序号
- [ ] 只读文件与 Markdown 预览中工具不可用
- [ ] 中英文下菜单与提示文案正确
