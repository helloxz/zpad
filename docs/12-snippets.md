# 代码片段

状态：**待签收**（未发布）

## 背景

ZPad 是轻量编辑器，日常写作和调试里有大量重复文本（`console.log`、Markdown 表格骨架、SQL 查询模板……）。这些内容不适合放进文件模板，也不值得每次都从别处复制。代码片段功能把这类短文本收进一个面板：分组管理、点一下就插到光标处。

## 需求

- 工具栏左侧工具组里，扳手按钮右边、信息按钮左边新增一个片段按钮；`⌥⌘S`（Windows / Linux 为 `Ctrl+Alt+S`）打开同一个面板。
- 菜单「编辑 → 代码片段」里有：插入片段…、用当前选区新建片段…。
- 面板一套视图做完所有事：左边是分组（最上面一行「全部」），右边是选中的那一组或全部片段，不再有单独的「管理」模式。
- 搜索框即时过滤，匹配分组名、片段名与正文；左栏显示每个分组的命中数，0 命中置灰。
- 选中某个分组后，如果查询在别的分组还有命中，右侧空状态提示「其它分组还有 N 个」并给一个「查看全部」按钮。
- 点片段行插入并关闭面板；行尾 ✎ 编辑、🗑 删除；点分组显示该组片段。
- 分组的新建 / 重命名 / 删除都在左栏表头：`✎` 重命名、`🗑` 删除选中的分组（选中「全部」时这两项置灰）、`＋` 新建分组；右栏表头的 `＋` 新建片段。
- `↑`/`↓` 选择、`↵` 插入、`Esc` 关闭；分组用鼠标点，点完焦点自动回到搜索框，`↑`/`↓`/`↵` 立刻可用。
- 切换分组后，右栏总是选中该分组的第一条（之前没有选中项时也是）：选择由应用层决定，并告诉 `ui.List` 不要按上一条片段的 key 回填。
- 插入位置是当前激活标签的光标处；有选区就替换选区；多光标时每个光标各插一份，一次撤销即可全部回退。
- 插入的正文按 LF 归一，**原样插入，不自动加换行**：块状片段在正文末尾自己带一个换行即可（插入后光标落到下一行，且不会留下空行或行尾空白），行内片段（`console.log`、`![alt](url)`）不会被多塞一个空行。
- 多行正文的后续行跟随光标所在行的缩进。
- 只读文件、Markdown 预览、Vim 模式开启时**不插入**，给出理由的 toast，面板不关闭。
- 新建片段写在当前分组；在「全部」时写在选中那条片段所在的分组；一条都没有时用 `default` 分组（按需创建，不再拿当前文件的语言起名）。
- 新建片段时，如果当前标签有选中的文本，正文与名称直接取它；名称取第一行。
- 编辑弹窗：名称只有一个带 placeholder 的单行输入（不再有「名称」这样的可见标题），正文有「正文」标题与多行输入，底部实时显示 `名称 12 / 40 · 正文 34 B / 8.0 KB`；标题下写明「所属分组：JavaScript」。分组弹窗同样只有一个输入框，placeholder 是「请输入分组名称」，下面是 `0 / 40`。
- 名称规则：折叠连续空白（换行、Tab 变成空格）、剥掉控制字符、去掉首尾空白；**最多 40 个字符**（按字符数，中英文都是 40），不能为空，同一层不能重名（大小写不敏感）。名称是标签不是路径，`/`、`\` 不拦。
- 上限：整库最多 **100 个片段**，单个片段正文最多 **8 KB**（UTF-8 字节）；超出的创建 / 修改会在弹窗里被拦下。列表里过长的名字用中间省略号截断，不会挤走计数和操作图标。
- 非目标：占位符与 Tab 跳转（`$1` / `${1:name}` 按字面插入）、按语言自动筛选、自动补全前缀、导入导出、云同步、拖动排序。

## 交互

```
工具栏：… 🔧 [<>] (i) …
              └─ 点击打开片段面板

面板（居中卡片，与跨文件搜索同一套样式）
├── 标题「代码片段」
├── 搜索框
├── 左栏（160）：分组 ✎ 🗑 ＋      右栏：组名 / 全部片段 ＋
│   ├── 全部        6              └── 片段行（名称 + 首行预览 + 来源分组）
│   ├── JavaScript  3                    ← 点击或 ↵ 插入，行尾 ✎ 🗑
│   ├── Markdown    2
│   └── Shell       1
└── 底部：↑↓ 选择 · ↵ 插入 · Esc 关闭        共 N 个片段
```

- 「全部」只显示在左栏，不落盘；选中它时右栏每行末尾显示来源分组，表头写「全部片段」。
- 两栏表头用同一个高度常量（`snippetHeaderHeight`），框的顶边因此始终对齐。
- 新建的片段写入哪个分组，编辑弹窗顶部会写出来，保存前就能看见。
- 面板打开时工具栏按钮保持高亮；`Esc` 与点击遮罩都由 `DialogBase` 处理。
- 删除分组时若组内还有片段，先用原生确认框问一次；单个片段的删除也会确认，因为片段是手写内容且没有撤销。
- Vim 模式开启时，面板底部显示「已开启 Vim 模式，不能插入片段」，插入被拒绝，增删改照常。

## 存储

`<用户数据目录>/snippets.json`，与 `settings.json`、`session.json` 同级，`0600`，经 `internal/atomicfile` 原子写：

```json
{
  "version": 1,
  "groups": [
    {
      "id": "g_9c1d2e3f4a5b",
      "name": "JavaScript",
      "snippets": [
        { "id": "s_1a2b3c4d5e6f", "name": "console.log", "body": "console.log(x);" }
      ]
    }
  ]
}
```

- `id` 用 `crypto/rand` 生成，重命名只改 `name`，引用不断。
- `body` 是字符串（`\n` 换行），不是 VS Code 的行数组；未知字段不保留。
- 文件损坏时另存为 `snippets.json.bak` 并当作空库启动；手写文件缺 id 会补齐，CRLF 会归一为 LF，没有名字的分组 / 片段会被丢弃。
- 每次增删改都整文件重写；只在用户动作时写，不在输入框里逐字写。

## 实现

- `internal/snippets/`：模型、`Load` / `Save`（原子写、损坏落 `.bak`）、`repair`（补 id、归一换行、只丢空名）、增删改与校验（`normalizeName` 折叠空白并剥控制字符，`cleanName` 再校验空名与 40 字上限；重名、正文非空、8 KB、100 条）。加载走 `normalizeName` 而不是 `cleanName`：手写文件里超长的名字**保留**，编辑时再要求改短，避免升级后凭空丢数据。错误用 sentinel（`ErrNameTaken` 等），由界面映射成文案。
- `internal/app/snippets.go`：面板状态、行模型（分组标题 + 片段行）、过滤（`foldContains` 不复制正文，逐字节 `EqualFold`）、键盘选择、`insertSnippetText`、从选区新建、增删改的收口与文案映射。
  - 插入不走 `State.Insert`（它会经过粘贴路径，可能把文本当作「整行粘贴」放到光标上一行），而是对每个选区从后往前 `Buffer.Edit`，`Buffer.Transact` 合成一步撤销，再把每个光标放到插入文本之后。
  - 插入按选区逐个对齐缩进（`alignSnippet`，复用 `tools.go` 的 `alignToLine`）；正文以换行结尾时不留末尾缩进，并且光标在行尾时连这一行自己的换行一起替换，所以块状片段不会多出一个空行。
- `internal/app/snippets_ui.go`：一套面板（左栏分组 + 右栏 `ui.List` 虚拟化列表）、片段编辑弹窗、分组弹窗。两栏表头都高 `snippetHeaderHeight`（26），左栏是「✎ 🗑 ＋」三个 22px 图标按钮（前两个在「全部」视图下 `Disabled + DimDisabled`），右栏只有一个「＋」；行内因此没有任何额外控件，分组行与「全部」行等宽。
- `internal/app/view.go`：工具栏按钮、`⌥⌘S`、浮层注册、`Esc` 守卫。
- `internal/app/menu.go`：编辑菜单的「片段」子菜单。
- `internal/app/icons.go`：`iconSnippets`（尖括号方块）、`iconEdit`、`iconTrash`。
- 文案：中英各 34 条，`go tool mygo generate` 生成。

## 内存

- 常驻是分组与片段的字符串：100 条 × 8 KB 的极端情况约 800 KB，典型几十条不到 100 KB。
- 读取时一次性解码（文件字节 + 解码字符串，约为文件的 2–3 倍），随后回收；面板打开时才读，关闭后不再持有额外结构。
- 列表是虚拟化的 `ui.List`，每帧只构建可见行 + 4 行；预览只取正文首行，不复制全文。
- 单条 8 KB 与整库 100 条的上限保证最坏常驻不到 1 MB，相对 60–75 MB 的基线可以忽略。

## 已知限制

- 不支持占位符：正文里的 `$0`、`${1:name}` 按字面插入。
- 不自动补换行（也没有「插入后换行」开关）：要换行就在正文末尾自己按一下回车。
- 不支持拖动排序，顺序就是文件里的顺序；分组与片段都只有新建时追加到末尾。
- 上限固定（100 条 / 8 KB / 名称 40 字），不提供设置项；手改 `snippets.json` 可以绕过，读取时不截断也不改名。
- 每次打开面板都会重新读文件，所以手改的内容会被看到；但如果在 ZPad 里用编辑器打开 `snippets.json` 改了又没保存，接着在面板里改片段，后一次写入会覆盖手改的内容。
- 没有导入 / 导出，也不兼容 VS Code 的 `.code-snippets` 格式。
- 不恢复上次的分组与搜索词；每次打开都是「全部」加空查询。
- 左栏只支持鼠标，`Tab` 不会把焦点移到分组上；键盘操作集中在搜索框、`↑`/`↓` 与 `↵`。
- 「全部」不是真实分组，不能重命名或删除，也不会出现在 `snippets.json` 里。
- 片段正文是纯文本，不会按文件语言高亮。
