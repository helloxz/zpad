# 03 · M2 左右双栏与会话恢复

> 预估：1–2 天
> 前置：M1 已签收

## 1. 目标

把单栏编辑器扩展为**左右双栏 + 每栏独立标签**，并让窗口在下次启动时
恢复工作区、标签、分屏和滚动位置；同时补齐关闭 / 退出时的未保存汇总提示。

## 2. 范围

### 做

- 左右两栏，中间可拖拽分隔线。
- 每栏独立的标签列表、当前标签、光标与滚动。
- 分屏开关、关闭右栏并合并标签。
- 活动栏跟随焦点；工具栏、菜单、状态栏作用于活动栏。
- 会话保存与恢复。
- 关闭标签 / 关闭窗口 / 退出应用的未保存提示。
- 窗口标题、macOS 关闭按钮的未保存状态。
- 测试。

### 不做

- 三栏以上（上下分屏已于 0.1.0 后续支持，见「实现记录」）。
- 标签拖拽排序（后续已实现，见「实现记录」）。
- 热退出恢复未保存内容（二期）。
- 外部修改监听（二期）。

## 3. 数据模型

```go
type Tab struct {
    doc   *Document
    state *editor.State
}

type Pane struct {
    tabs   []*Tab
    active int
}

type Workspace struct {
    root       string
    docs       map[string]*Document // 按绝对路径去重
    left       Pane
    right      Pane
    split      bool
    splitWidth float32
    activePane int // 0=左 1=右
}
```

- 同一个文件可以在左右两栏各有一个标签：共享 `Document.Buffer`，但各自有 `editor.State`，光标与滚动互不影响。
- `docs` 以绝对路径为键；最后一个标签关闭时视情况从 `docs` 移除。
- 右栏关闭时，把右栏标签并入左栏，按路径去重。

## 4. 任务拆解

### 4.1 分屏布局

- [ ] 根内容区：

```go
if app.split {
    ui.Split(c, &app.splitWidth, app.leftPane, app.rightPane).Fill()
} else {
    app.leftPane()
}
```

- [ ] 使用 `ui.Split`，分隔线默认宽度 50%，最小保留 40 DIP。
- [ ] `splitWidth` 持久化；窗口过窄时由 `ui.Split` 自身收缩。
- [ ] 工具栏提供“切换分屏”按钮；`Cmd+\` 快捷键。
- [ ] 分屏开启时，右栏默认打开当前文件的一个新标签（复制当前文档引用，新建 `editor.State`）。
- [ ] 关闭右栏：
  - 把右栏标签并入左栏。
  - 相同路径只保留左栏的一份。
  - 活动栏切回左栏。
  - 右栏的空状态不保留。

### 4.2 每栏独立标签

- [ ] 左栏、右栏各自渲染自己的标签栏。
- [ ] 每个标签独立保存：光标、选区、滚动、折叠状态。
- [ ] 切换栏或标签时，焦点请求到对应的编辑器。
- [ ] 活动栏判断：
  - 任一标签的 `state.Focused()` 为真 → 该栏为活动栏。
  - 点击标签栏、状态栏操作的栏也要能主动设为活动栏。
- [ ] 标签关闭后，若该栏为空，显示该栏的空状态，不自动关闭整栏。
- [ ] 同一文件在两栏同时打开时，编辑任一侧，另一侧同步显示（共享 Buffer）。

### 4.3 状态栏与命令作用域

- [ ] 状态栏显示活动栏当前标签的信息。
- [ ] 保存、另存为、关闭标签、查找、大小写等命令作用于活动栏。
- [ ] 侧栏打开文件时，默认进入活动栏。
- [ ] 工具栏的“保存”“撤销”等按钮根据活动栏状态启用 / 禁用。

### 4.4 会话保存

- [ ] 扩展 `session.State`：

```go
type TabState struct {
    Path    string  `json:"path"`
    ScrollY float32 `json:"scrollY"`
}

type PaneState struct {
    Tabs   []TabState `json:"tabs"`
    Active int        `json:"active"`
}

type State struct {
    Root         string    `json:"root"`
    Split        bool      `json:"split"`
    SplitWidth   float32   `json:"splitWidth"`
    ActivePane   int       `json:"activePane"`
    Left         PaneState `json:"left"`
    Right        PaneState `json:"right"`
    SidebarOpen  bool      `json:"sidebarOpen"`
    SidebarWidth float32   `json:"sidebarWidth"`
}
```

- [ ] 保存时机：
  - 窗口关闭前。
  - 应用退出前。
  - 布局变化后防抖 1 秒（可选）。
- [ ] 恢复时机：
  - 窗口创建后、第一帧之前读取。
  - 依次打开文件；缺失文件跳过并 toast 提示。
  - 恢复活动标签与滚动位置。
- [ ] `settings.RestoreSession` 为 false 时，只恢复窗口大小，不恢复标签。
- [ ] 会话写入使用原子写，损坏时回退为空会话。

### 4.5 关闭与退出

- [ ] 统一的关闭协调器，避免窗口关闭与退出重复弹窗：

```go
type closeRequest struct {
    reason string // "tab" | "window" | "quit"
    done   chan bool
}
```

- [ ] 关闭单个标签：只检查该标签。
- [ ] 关闭窗口 / 退出：收集所有栏中所有未保存文档（按路径去重）。
- [ ] 汇总对话框：

```text
有 3 个文件未保存，是否保存？
[保存全部] [不保存] [取消]
```

- [ ] 保存全部：
  - 逐个保存；未命名文件走另存为。
  - 任一取消或失败 → 中止关闭，保留窗口。
- [ ] 不保存：直接关闭 / 退出。
- [ ] 取消：中止关闭。
- [ ] 关闭协调器需要重入保护：对话框打开期间再次触发关闭应被忽略。
- [ ] macOS `Cmd+Q` 通过 `App.OnBeforeQuit` 进入同一流程。
- [ ] 关闭完成后清理会话、保存窗口状态。

### 4.6 窗口状态

## 7. 风险与备注

- `ui.Split` 只支持两个窗格，正好满足一期“只做左右两栏”。
- 关闭协调器必须防止 `OnClose` 与 `OnBeforeQuit` 互相触发导致的重复对话框。
- 恢复滚动位置需要在编辑器完成首次布局后设置，必要时延迟一帧。
- 同一文件双栏共享 Buffer 是 MyGo 编辑器原生支持的能力；仍需验证撤销历史与选区同步行为。

### 后续增强：标签拖拽排序（2026-11-23）

补上原计划留到二期的栏内拖拽排序，跨栏拖拽一并在同一套管线里统一：

- 标签栏的 `ui.ScrollHorizontal` 本身成为 `paneDrag` 的放置目标：`ui.DragOver` 给出正在拖的标签，`Element.PointerPosition()` 给出指针在栏内的 x，与各标签上一帧的 `Bounds()` 中线比较得到插入索引，`DrawOver` 在落点画一条 2px 强调色竖线；放在标签自身位置或右侧紧邻位置时不画线也不移动。
- 落点计算与 MyGo `ListState.Reorder` 同一思路（`dropAt` + 上一帧边界），拖拽源是放置目标的子孙，和列表拖自己行的机制一致。
- 同栏：`reorderTab` 取出再按 `to` 插回（`to > idx` 时先减一），活动标签仍是原来那一份（按标签指针找回索引），不随拖拽切换；重排后 `saveSession()`，重启按新顺序恢复。
- 跨栏：`moveTabAt` 支持目标索引，`moveTabIndex` 退化为「追加到末尾」的包装；落在另一栏的标签栏按位置插入，落在编辑区仍追加到末尾；目标栏已有同一文档时只激活它，不产生重复标签。
- 侧栏文件拖到标签栏沿用原有行为（在目标栏追加打开），并在此帧用一条底部强调线提示可以放下。
- 分屏分隔线有一圈抓取区域盖在两侧栏上，落在抓取区里的拖拽没有目标；这是既有行为，未改动。
- 不做拖拽到栏边缘时自动滚动标签栏：溢出时先滚动再拖。
- 测试覆盖：`tabDropAt` 边界、栏内重排（含活动标签保持、拖到自身无操作）、`ui.Tester` 真实拖拽重排、跨栏按位置插入、落在本栏无位置时无操作。

### 后续增强：标签栏空白双击新建（2026-11-27）

按 issue #18 补上浏览器与主流编辑器的习惯手势：

- 标签栏的 `ui.ScrollHorizontal` 挂 `HandleInput`：`InputPointerDown`、主键、`Clicks == 2` 时用该栏的 `index` 调 `addDocumentAt(index, newUntitledDocument())`，新文件落在该栏末尾、成为活动标签并聚焦，与点该栏 `+` 一致。
- 只认真空白：标签自带 `HandleInput`（中键关闭），`+` 号也挂一个不处理输入的 handler，事件停在那里，不会落到标签栏的处理器上；标签排满时标签行铺满整栏，双击不会再新建，仍用 `+` 或 `⌘N` / `Ctrl+N`。
- 单击空白不做事；三击只在第二下建一个（`Clicks == 2`）。
- 测试覆盖：空白双击新增并聚焦、单击不新增、双击标签不新增、双击 `+` 只新增一个、非活动栏的空白双击落在该栏并激活它。
- 不做：标签排满时预留空白区，也不加设置项。

### 后续增强：工作区单击打开预览标签（2026-11-27）

按用户反馈「单击只想浏览，不想留下标签」补上主流编辑器的预览标签：

- 工作区树单击文件仍立即打开，但开成预览标签：`Tab.temporary` 为真，同一栏最多一个，下一次单击用 `replacePreviewTab` 在同一位置换掉它，标签总数不增加；已打开的文件只激活，不重复开。
- 替换不经过 `removeTab` 再 `append`：副栏只有这一个标签时那样会先清空该栏、触发分屏收起，再把新标签加到不存在的栏里。原地换 `doc` / `state`，旧文档走抽出的 `forgetClosedDocument`，清理搜索、对比、预览选项与草稿（大文档仍触发 GC）。
- 固定时机：双击行、双击标签、开始编辑（每帧 `pinModifiedTabs` 检查 `Buffer.Modified()`）、保存、拖到另一栏、标签右键「固定标签」。同一文档在任何栏永久打开时，`pinDocument` 把两栏该文档的预览标签一起固定。
- 文件还在后台读取时双击也生效：`pinPath` 把路径记进 `pinPending`，读取完成后的 `addDocumentAtMode` 直接开成永久标签。
- 只有工作区树单击走预览；右键「在副窗口打开」、拖拽、命令行、搜索结果、会话恢复都仍是普通标签。设置 → 工作区新增「单击打开为预览标签」，默认开，关闭后回到每次单击都开新标签。
- 预览标签名用斜体；悬停提示显示路径加「预览标签：双击或编辑后保留」；标签右键菜单顶部多一项「固定标签」（仅预览标签出现）。会话不写新字段，预览标签按普通标签保存与恢复。
- MyGo 的双击第二下 `Clicked()` 也为真，`treeRow` 先判 `DoubleClicked()` 再判 `Clicked()`，文件夹的双击不再切换两次。
